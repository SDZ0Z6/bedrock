这一页怎么读

  • 配额是账号级的全局池，不分区域。 名字里的 Global cross-region 就是字面意思：四个美区共用同一份额度。实测四个区 返回的值完全相同，所以这一页没有区域维度，只查一个区（{{ quota_region }}， 它列出的模型最全）。
  • 配额口径是输入 + 输出 token 合计， 覆盖 Converse、ConverseStream、InvokeModel、InvokeModelWithResponseStream 全部请求。
  • 「日 ÷ 分」是两条配额自己的比值，不涉及任何实际用量。 正常应该是 1440（分钟配额跑满 24 小时刚好等于日配额）。 偏离 1440 的会标黄——说明这个模型的两条配额不是按整天配的， 实际瓶颈会先落在其中一条上。
  • Model ID 是调用时真正要传的那个， 取自 bedrock:ListInferenceProfiles 的 SYSTEM_DEFINED 跨区推理配置（global.anthropic.*），不是从配额名拼出来的。 配额名里只有显示名，没有可调用的 ID。
  • 1M 上下文长度是独立的一条配额， 和同名模型的普通配额各走各的，不共享额度。它没有单独的 global 配置， 所以 Model ID 一列是空的——用普通模型的 ID 调用，靠请求里的上下文设置区分。
  • 两条配额的可调性不一样：日配额 Adjustable=false， 改不了；分钟配额 Adjustable=true，可以直接在 Service Quotas 控制台申请提额。实测 12 个模型全部是这个组合，所以 TPM 撞上限时是有办法的， 日配额撞上限只能找 AWS。
  • 配额和实际用量的对比不在这一页——「模型用量」页有各模型按时间的 token 走势，需要的时候可以拿这里的数字去比。
